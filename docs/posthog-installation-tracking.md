## Metrics

| Event | Meaning |
|---|---|
| github_app_installation_created | Successfully handled, signed installation.created webhook |
| github_app_installation_deleted | Signed uninstall; erasure scheduled, not proof erasure completed |
| github_app_installation_suspended / github_app_installation_unsuspended | Suspension lifecycle, never a new install |
| github_app_permissions_accepted | Updated permissions accepted |
| github_app_repositories_changed | Repository access additions/removals, with counts |
| github_app_installation_snapshot | Hourly observation of each installation returned by GitHub, including zero-repository installations |
| github_app_inventory_snapshot | Latest hourly total, active, external and active-external installation counts |
| shadow_first_prediction_recorded | First retained prediction per installed repository, timestamped at its original creation; pre-September-10 rows labeled is_backfill |
| shadow_report_served | Successful backend report response; not a verified human read, and caches may prevent a new request |
| diffci_analytics_verified | One idempotent operator test, is_test=true and is_internal=true |

Use the **latest** inventory snapshot property for current counts, not a sum across snapshots. Use distinct installation_key for unique installation conversions. For external conversion funnels filter is_internal=false, is_test=false, and exclude backfills where appropriate. Existing installations are represented by snapshots, not fabricated creation events. Repository count in webhook events describes that payload; observed_repository_count in snapshots is the D1 enrollment count, not an authoritative GitHub repository-access count.

The hourly snapshot is generated by the existing ten-minute cron. GitHub REST /app/installations, with full pagination, is authoritative for inventory; a failed fetch emits no partial inventory. This catches installs even if no repositories are selected. Suspended installations are excluded from active counts. Account adityankale190895 is internal (case-insensitive); extend this explicit classification when more internal accounts are added.

## Delivery and privacy

The authenticated Shadow webhook writes to a D1 outbox before acknowledging successful lifecycle handling. If that write fails, it returns 503 so delivery can be retried. Outbound errors are recorded and retried by the existing cron. First receipt persists the UUID, timestamp, and payload, so retries preserve PostHog's deduplication tuple. Source: https://posthog.com/docs/data/events#event-deduplication.

Stable installation/repository/event keys use HMAC-SHA256 with a dedicated secret. No raw account names, repository names, source, report tokens, GitHub delivery identifiers, or emails are sent. Person-profile processing and GeoIP are disabled. Keep POSTHOG_IDENTITY_SALT stable: changing it breaks historical identity continuity. Only the write-only project token is needed; no PostHog personal read/admin key is installed in the Worker.

Report telemetry runs after the report's access check. It may include bots and refreshes and is best effort if the initial database write fails. First-prediction telemetry is reconciled from durable prediction records, so it does not depend on a browser staying open. These limitations must remain visible in dashboards.

## Operation

Apply src/research/cloudflare/schema-migration-2026-09-10-posthog.sql before deploying. Configure POSTHOG_API_KEY for project 599109 and POSTHOG_IDENTITY_SALT as Worker secrets. POSTHOG_HOST defaults to https://us.i.posthog.com.

Bearer-authenticated operator endpoints:

- POST /v1/shadow/analytics/verify: enqueue and deliver the labeled integration test (idempotent).
- POST /v1/shadow/analytics/sync: refresh real inventory, reconcile first predictions, and retry delivery.
- GET /v1/shadow/analytics/status: configuration presence and total/pending outbox counts; never returns credentials.

Use the canonical shadow deployment pipeline so the Worker and analyzer archive retain matching commits. The generic product/observer App's legacy aggregate helper is separate and is not the Shadow installation authority.
