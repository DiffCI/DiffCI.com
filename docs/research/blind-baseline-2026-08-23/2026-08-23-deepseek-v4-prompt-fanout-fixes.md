## 1. FATAL — move orchestration out of `ctx.waitUntil`
`src/analysis-fanout/cloudflare/analysis-fanout-worker.ts:441` does `ctx.waitUntil(runFanOut(env, doStub, tasks))`, and `runShard` contains a `while (true)` poll loop that lasts for the lifetime of a shard (bootstrap + clone + several merges ≈ 15–40 min). A Worker's `waitUntil` only extends a request by a bounded grace period (seconds to minutes). The fan-out will be terminated mid-flight and the watchdog will then mark every shard failed. This is the same class of bug as the 580 s `exec` cap, one level up.

Required redesign:
- Orchestration must live in Durable Objects, driven by `alarm()` re-scheduling, so nothing depends on a request lifetime. Recommended shape: one `AnalysisShard` DO per shard (the Sandbox container is itself a DO — you may make the shard state machine live on the container DO or on a thin sibling DO that owns a Sandbox by name). The `AnalysisRun` coordinator DO keeps run-level state, fans out by calling each shard DO's `POST /start` (which must return immediately after persisting state and setting its first alarm), and aggregates heartbeats.
- The shard state machine persists its step in DO storage (`bootstrapping → cloning → analyzing → finalizing → done|failed`) and advances one bounded step per `alarm()` invocation. Each step must finish well inside a single DO invocation: bootstrap/clone are single `exec` calls with explicit timeouts; the analysis step uses `startProcess` once and then each subsequent alarm only polls `getProcess`, ingests new rows, uploads them, heartbeats, and re-schedules (`POLL_MS` ≈ 15–30 s). No `while (true)` anywhere in Worker or DO code.
- Idempotency: if an alarm fires twice or the DO is evicted and restored, the step must resume from persisted state without re-cloning, re-extracting, or duplicating rows (track `flushedLines` and the process id in storage).
- `SHARD_CONCURRENCY` becomes a run-request parameter (`maxConcurrentShards`, default 8), enforced by the coordinator releasing the next shard when one reaches a terminal state — not by an in-memory `mapWithConcurrency` inside a request.
- Keep what was right: `startProcess` for the replay (no 580 s cap), live-shape probe before trusting results, per-row partial R2 upload, exit 137 → row-level `resource-kill` with no verdict, original manifest `index` preserved, watchdog alarm for stale heartbeats (keep 35 min).

## 2. Make the engine-checksum gate trustworthy
Today `POST /v1/run` compares a **client-supplied** `engineChecksum` string to the frozen manifest in R2, and the in-container `verify-frozen-engine.cjs` verifies the extracted tree against the manifest **inside the same tarball**. A modified tarball with a regenerated manifest passes both checks.
- The Worker must hash the tarball object itself (stream the R2 object through `crypto.subtle.digest` / Web Crypto SHA-256 in the Worker, or rely on R2's stored `sha256` checksum set at upload time with `--sha256`) and compare that to a `tarballSha256` recorded in the **R2 copy** of the frozen manifest's companion record `manifests/<runId>/pack-record.json` written by the CLI `pack` step. Reject the run on mismatch.
- Inside the container, download the frozen manifest **from R2** (trusted copy) to `/opt/frozen-manifest.json` and run the verifier against it, not against the copy that came in the tarball. Add a `--manifest <path>` argument to `verify-frozen-engine.cjs` ONLY if you can do so without changing its default behaviour (it is a harness file, not engine; document the change in the run record). Abort the shard with `failed: engine-drift` on mismatch.
- After extraction, also `sha256sum /opt/diffci-source.tgz` and compare to the pack record; abort on mismatch (`failed: tarball-corrupt`).

## 3. Tarball transfer robustness
`sandbox.writeFile("/opt/diffci-source.tgz", tar.body)` relies on the SDK accepting an R2 `ReadableStream<Uint8Array>` for a multi-MB binary. Verify it on a real deploy with the checksum from item 2; if it corrupts or truncates, switch to a pre-signed R2 URL fetched with `curl --fail --max-time 600 -o /opt/diffci-source.tgz` inside the container. Either way the post-transfer checksum check is mandatory.
