# DiffCI 0.3.0

> The `v0.3.0` publishing workflow stopped during dependency installation before npm publication.
> The tag is retained as an immutable audit record; the stable package was published as 0.3.1.

DiffCI 0.3.0 makes fail-closed verification discoverable by AI coding agents. `diffci init` can install
persistent repository instructions and a verification workflow, while `diffci verify --changed --json`
returns a machine-readable receipt that tells an agent whether it is safe to continue.

The release candidate was exercised in two repositories before stable promotion:

- [DiffCI.com](https://github.com/DiffCI/DiffCI.com/pull/14) installed the agent defaults, passed its
  2,326-test self-verification run, and made `DiffCI verification` a strict required check on `main`.
- [DentalPresence.in](https://github.com/adityankale190895/DentalPresence.in/pull/115) installed the
  published release candidate and passed DiffCI verification, its full test evidence workflow,
  typechecking, linting, and portability checks. Its private GitHub plan does not support formal branch
  protection, so the workflow is fail-closed but cannot be configured as a required status check.

These pilots qualify the installation and agent-verification path across two real repositories. They do
not establish independent adoption, realized savings, or the seven-day private-alpha evidence threshold.
The observer remains conservative, existing CI remains authoritative, and refusal or analysis errors do
not authorize an agent to skip required tests.
